Forms

The controls of a form: text area, number input, select, checkbox, radio group, switch, segmented, date and time inputs, combobox and file drop zone, and the search field as a pattern. Each one sits in a field, which gives it its label, its help and its error; the field and the text input are on Foundations.

Date and time

Focus on a part of the value rings the box, and the browser highlights the part. Focus on the button rings the button; where the browser draws its own button, the ring is its own too.

Dark, compact, right to left

Decided: the date and time inputs are the native controls. They carry the design for one date, one time, or a date with a time. In the box of the text input it has the height, the border, the type, the three sizes and every state of the other controls, in both themes and in both densities, and it posts in a static form. A custom calendar is not needed for these, and the library ships the native inputs.

What falls short, as checked in Chromium and Firefox:

  • An empty input shows its pattern, such as mm/dd/yyyy, in the colour of a value. No selector tells an empty date from a filled one, so it cannot take the colour of a placeholder.
  • The part of the value that has focus is painted in the highlight colour of the system, not in the accent: the browser does not let that rule be replaced.
  • The format, the first day of the week and the twelve or twenty-four hour clock come from the language of the browser, not from the page or from the culture of the application.
  • In Chromium the direction comes from the language of the browser too: in a right-to-left page seen in a left-to-right browser, the value stays at the left of the box and the button at the right. Firefox follows the page.
  • The calendar and the list of times are drawn by the browser. They follow the theme through color-scheme, and nothing else of them can be styled: not the accent, the radius or the type.
  • Only Chromium and Safari let the button be reached, so only there it shows the icon of the library; Firefox draws its own calendar button and has no list for a time. Safari was not checked.
  • There is no range in one control, no shortcut such as Today or Last 7 days, no time zone, and no way to mark single days as unavailable: only min and max.

A custom calendar is needed where one of these is required: a range of dates in one control, such as the filter of a table; a format that the application fixes whatever the browser; or a calendar that must look like the product. It would be an Interactive component of its own, a date picker with this input as its static fallback, and it is not part of this lane.

Element<div class="fl-combobox"> with two children. The box, <div class="fl-combobox__box">, holds fl-combobox__values (the tags, then <input class="fl-combobox__input" role="combobox">) and one or two <button class="fl-combobox__action">. ARIA and keys
  • The combobox pattern with a list box popup and list autocomplete. On the input: role="combobox", aria-expanded, aria-controls the list, aria-autocomplete="list", and aria-activedescendant the option under the keys. Focus never leaves the input.
  • Arrow down and Arrow up open the list and move through it; Enter chooses; Escape closes the list, and a second Escape clears the input; typing filters; Home and End move the caret.
  • Chosen options carry aria-selected="true"; with several choices the list carries aria-multiselectable="true" and stays open after a choice.
  • Each tag has a button named Remove and the name of its option; Backspace in the empty input removes the last tag. The button that opens the list is out of the tab order.
  • The status has role="status", so No option matches and Searching are read; a list that is loading carries aria-busy="true".
  • The option under the keys carries data-fl-active: CSS cannot follow aria-activedescendant to an element, so the component sets both.
LevelInteractive. The static fallback is a fl-select with the same options, and a set of checkboxes for several choices.

    ARIA and keys
    • The control is the native file input, named by the label of its field; the hint is in aria-describedby. Tab moves to it; Space or Enter opens the dialog of the browser.
    • The words Drop files here, or browse are text, not a second control: the input lies over all of the area.
    • The list has a name and aria-live="polite", so a file that is added, done or failed is read. A file that is being sent carries aria-busy="true", and its <progress> has a name.
    • Each action of a file is a button with the name of its file: Cancel, Remove, Try again. After a file is removed, focus moves to the next one, or back to the input.
    • While files are held over the area it carries data-fl-dragover: there is no selector and no ARIA state for a drag.
    • Invalid: aria-invalid="true" on the input. Disabled: disabled.

    • A native search box in a search landmark. It has a name: aria-label, since it shows no label.
