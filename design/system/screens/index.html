Screens

Four screens of the FluentCMS admin, composed from the library's CSS alone. They prove that the components hold together: each screen is the markup of the component pages, joined, with the content of the reference design.

Reference screens

Every screen has the same frame: the app shell with the navigation, and the header with the breadcrumb, the global search, the locale, the notifications and the user menu. A screen opens without the chrome of these pages; a small bar at its end holds the theme, the density and the direction, and the links between the screens.

ScreenWhat it proves
DashboardThe frame, and a page of cards: stat tiles with their charts, a table, a timeline, progress bars and a description list side by side in two columns, and the split button with its menu.
Content listA list of records in one card: tabs as saved views, the toolbar with its filters and its selection form, the table with selection, badges, avatars and row actions, the pagination, and a dialog that confirms a deletion.
Entry editorA long form beside a column of details: the page header of an item with its state, as a bar that stays in view with the actions that save and publish; tabs for the locales; fields with counters, an affix and an action; a sortable list of blocks that open; and cards with an alert, a popover, comboboxes, a timeline and a description list.
SettingsA form of settings in cards of horizontal fields: every form control once, with its help; one invalid field with the alert that points at it; a file drop zone; a dialog that confirms a deletion by a typed name; and the toast of a save.

What the screens add to the library is in one file. screens.css holds the layout rules that a screen needs and the library lacks. Every rule in it names the missing pattern, part or variant that would make it unnecessary.
